# Пз3 - PostgreSQL і Prisma

Дані з Пз2 живуть у масиві й зникають при кожному перезапуску `tsx watch`.
Сьогодні вони переїжджають у PostgreSQL. Головне спостереження практичної:
**контракт API не змінюється**. Ті самі адреси, ті самі коди, той самий
`npm test` - і він має лишитися зеленим.

## Як підняти базу

**З Docker** (основний шлях, знадобиться в Пз7):

```bash
docker compose up -d db          # PostgreSQL за десять секунд
```

**Без Docker** - Prisma 7 вміє підняти локальний Postgres сама:

```bash
cd server && npx prisma dev
```

Вона надрукує `DATABASE_URL` - покладіть його у `server/.env`. Решта кроків
однакова. Docker усе одно доведеться поставити до Пз7, але сьогодні він
не обовʼязковий.

## Запуск

```bash
cd server
cp .env.example .env             # .env у git не потрапляє, .env.example - так
npm install
npx prisma generate                  # клієнт: migrate його НЕ створює
npx prisma migrate dev --name init   # створює таблиці
npx prisma db seed                   # наповнює базу демо-даними
npm test                             # сервер піднімати не треба
```

На чистому каркасі - **3 з 8**: працюють `/api/health` і список, решта
маршрутів ще не переведена на Prisma. Здано, коли **8 з 8** і дані
переживають перезапуск.

## Prisma 7: що змінилося порівняно з тим, що ви бачили раніше

Якщо гуглитимете туторіали, більшість із них - про Prisma 5 і 6. Чотири
відмінності, через які чужий приклад у вас не запуститься:

| Було (Prisma 5–6) | Стало (Prisma 7) |
|---|---|
| `url = env("DATABASE_URL")` у `datasource` | рядок підключення в `prisma.config.ts` |
| `generator client { provider = "prisma-client-js" }` | `provider = "prisma-client"` і обовʼязковий `output` |
| `import { PrismaClient } from '@prisma/client'` | імпорт зі згенерованої теки: `../generated/prisma/client.js` |
| `new PrismaClient()` | потрібен драйвер-адаптер: `new PrismaClient({ adapter })` |

Усе це вже налаштовано в каркасі - просто не дивуйтеся розбіжності з
туторіалами. Адаптер (`@prisma/adapter-pg`) - це те, що тримає пул зʼєднань:
саме тому `PrismaClient` створюється один раз на процес, а не в кожному маршруті.

## Підказки

**Звʼязок пишеться з обох боків.** `notes Note[]` у `User` і `author User @relation(...)`
у `Note`. Один бік без другого - помилка валідації схеми, а не половина звʼязку.

**`P2025` - це ваш 404.** `prisma.note.update()` на неіснуючому id кидає
помилку Prisma, і без обробки клієнт отримає `500`. Перевіряйте наявність
запису заздалегідь і кидайте `AppError(404, ...)`.

**`select` замість `include` у списку.** `include` тягне звʼязаний запис цілком.
У Пз4 у користувача зʼявиться хеш пароля - і `include: { author: true }`
чесно віддасть його клієнту.

**Міграції комітяться.** `prisma/migrations/` - частина коду: за ними колега
і CI відтворять базу з нуля. Уже застосовану міграцію не редагують - змінили
схему, зробіть нову.

**«Перший раз працює, другий - 409».** Це не баг коду, це брудна база: минулий
запуск лишив по собі записи. `npx prisma migrate reset --force && npx prisma db seed` піднімає базу
з нуля разом із даними.

**`npm install` - до будь-якої команди `npx prisma`.** Без установлених
залежностей `npx` мовчки тягне з реєстру НАЙСВІЖІШУ версію CLI (зараз це
Prisma 8), у якої інші команди - і ви отримаєте «No command registered for
`migrate`». Локальна CLI ставиться разом із залежностями.

**Порт 5432 зайнятий.** Якщо у вас уже стоїть свій PostgreSQL - змініть у
`docker-compose.yml` ліву частину на `"5433:5432"` і поправте порт у `.env`.

## Чого тут немає - і це навмисно

- **автентифікації.** Усі записи поки належать демонстраційному користувачу.
  Справжній автор і фільтр «лише свої» зʼявляться в Пз4 - і саме тому звʼязок
  із `User` варто зробити вже сьогодні;
- **транзакцій у складних сценаріях.** `$transaction` показаний у списку
  (`findMany` + `count`); більше поки не потрібно;
- **окремої тестової бази.** Тест прибирає за собою і ходить по вашій базі
  розробки. Окрема база для тестів - це зірочка нижче.

## Зірочки

- **`$transaction` на складеній операції** - коли одна дія міняє два записи.
- **Лог запитів.** Розкоментуйте `log: ['query']` у `src/lib/db.ts`, відкрийте
  список і порахуйте запити. Знайдіть у себе N+1 - або доведіть, що його немає.
- **Тест на окремій базі.** Шаблонний тест із `tests/notes.test.ts` ходить
  по базі розробки. Зірочка - друга база для тестів: `.env.test` з іншим
  `DATABASE_URL` і очищення через `deleteMany()` у зворотному порядку
  звʼязків: спершу нотатки, потім користувачі - інакше зовнішній ключ
  не дасть.

## Що здаємо

Репозиторій, у якому:

- `docker-compose.yml` і `.env.example` є, `.env` - немає;
- `prisma/migrations/` закомічено, і база піднімається з нуля однією командою;
- `npx prisma db seed` наповнює її демо-даними;
- `npm test` - 8 з 8;
- дані живі після `docker compose down && docker compose up -d db` - це
  покажете на захисті.
