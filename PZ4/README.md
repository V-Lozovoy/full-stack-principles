# Пз4 - автентифікація і авторизація

До сьогодні будь-хто міг створити і видалити будь-що. Сьогодні зʼявляються
двоє: користувач, який входить, і власник, якому належать записи.

Дві різні задачі, які легко переплутати:

- **автентифікація** - «хто ти». Токена немає або він недійсний → `401`;
- **авторизація** - «що тобі можна». Це не хук на вході, а **умова в кожному
  запиті до бази**: `where: { id, authorId: user.id }`. Забули її в одному
  маршруті - саме там і буде дірка.

## Запуск

```bash
cd server
cp .env.example .env                 # там зʼявився JWT_SECRET
npm install
npm run db:up                        # запустити базу даних (перед цим - мати Docker запущеним)
npx prisma generate                  # клієнт: migrate його НЕ створює
npx prisma migrate dev --name auth   # після TODO(1)
npx prisma db seed                   # demo@example.com і admin@example.com, пароль demo1234
npm run dev                          # термінал 1

npm run check                        # термінал 2: контракт, 8 пунктів
npm run check:auth                   # термінал 2: безпека, 9 пунктів
```

На чистому каркасі: `check` зупиняється на вході (маршрутів `/auth` ще немає),
`check:auth` дає **2 з 9**. Здано, коли **8 з 8** і **9 з 9**.

## Дев'ять перевірок безпеки

`npm run check:auth` - це той самий сценарій, який я проганяю на захисті.
Тести на Vitest лишаються зірочкою; **цей скрипт - вимога**.

| # | Перевірка | Чому саме так |
|---|---|---|
| 1 | реєстрація → `201`, без пароля у відповіді | хеш не має витікати навіть власнику |
| 2 | той самий email ще раз → `409` | конфлікт, а не `500` і не `200` |
| 3 | пароль із трьох символів → `400` | вимоги до пароля - на вході, а не в голові |
| 4 | логін → `{ token }` | |
| 5 | «немає такого» і «невірний пароль» - **однаковий текст** | різні тексти дозволяють за `401` перебирати чужі email |
| 6 | список без токена → `401` | |
| 7 | список із токеном → `200` | |
| 8 | підроблений токен → `401` | підпис перевіряється, а не просто «щось прийшло» |
| 9 | Боб не бачить, не змінює і не видаляє запис Аліси → `404` | **головний пункт практичної** |

Пункт 9 - це і є різниця між «є логін» і «є авторизація». Відповідь саме `404`,
а не `403`: `403` чесно повідомляє зловмиснику, що запис із таким id існує.

## Підказки

**`npm install` - до будь-якої команди `npx prisma`.** Без установлених
залежностей `npx` мовчки тягне з реєстру НАЙСВІЖІШУ версію CLI (зараз це
Prisma 8), у якої інші команди - і ви отримаєте «No command registered for
`migrate`». Локальна CLI ставиться разом із залежностями.

**`return reply` у хуку обовʼязковий.** `reply.code(401).send(...)` без `return`
не зупиняє запит: Fastify піде в обробник і виконає його вже після того,
як відповідь пішла клієнту.

**Сіль окремим полем не зберігають.** bcrypt генерує її сам і кладе всередину
рядка хеша. У схемі є тільки `password`.

**Роль - лише з токена.** `role: "admin"` у тілі запиту від клієнта не означає
нічого. Читаємо `req.user.role`, який туди поклав `jwtVerify` після перевірки
підпису.

**Адміна призначають руками в базі.** Ендпоінта «зроби мене адміном» не існує
і існувати не повинно. `seed.ts` створює `admin@example.com`; можна й через
`npx prisma studio`.

**`expiresIn` - найлегший рядок, щоб забути.** Токен без строку життя живе
вічно, і його витік означає доступ назавжди.

**`ownedWhere` - одна функція на `GET /:id`, `PATCH` і `DELETE`.** Три копії
однієї умови - це три місця, де можна помилитися, і одне, де помилку не
помітять.

## Чого тут немає - і це навмисно

- **refresh-токенів.** Лише access на годину; вихід = клієнт забуває токен.
  Refresh - зірочка;
- **скидання пароля і підтвердження пошти.** Це окрема інфраструктура (лист,
  одноразовий код, строк дії) і не тема курсу;
- **обмеження частоти запитів.** Перебирати паролі на `/auth/login` поки
  можна тисячу разів на секунду. `@fastify/rate-limit` - зірочка;
- **httpOnly-cookie.** Токен поки віддається в тілі, і клієнт на Пз5 покладе
  його в `localStorage`. Чому це компроміс - на Л6.
