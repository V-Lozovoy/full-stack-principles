# Пз6 - повноцінне SPA з мапою

Клієнт у теці `client/` - це **робоче рішення Пз5**: `useState`, `useEffect`,
`load()` руками і тернарник замість маршрутів. Спершу запустіть його і
переконайтесь, що він працює.

Задача Пз6 - перевести його на три бібліотеки та додати мапу. Усе вже
варто в `package.json`, ставити нічого не треба:

| Бібліотека | Що забирає на себе |
|---|---|
| **React Router** | адреси, історія, кнопка «назад», вкладені layout-и |
| **Zustand** | сесія, доступна і компонентам, і функціям поза деревом |
| **TanStack Query** | кеш серверних даних: стани, повтор, `invalidate` |
| **react-leaflet** | мапа OpenStreetMap з маркерами нотаток на головній |

Обидва провайдери (`BrowserRouter`, `QueryClientProvider`) і дефолти
`QueryClient` у `main.tsx` **уже в каркасі**

## Запуск

```bash
cd server && cp .env.example .env && npm install
npx prisma generate && npx prisma migrate dev && npx prisma db seed && npm run dev

cd client && npm install && npm run dev
```

### Крок 1 - стор сесії

У `store/session.ts` практично весь код уже написано у підказці файла:
`create()(persist((set) => ({ token, email, login, logout }), { name: 'session' }))`.
Потім у `api/client.ts`:

- `getToken()` → `useSession.getState().token` (це звичайна функція, не хук,
  тому працює поза компонентом);
- `handleUnauthorized` → `useSession.getState().logout()` замість `setToken(null)`;
- `setToken` взагалі зникає: `LoginPage` після вдалого входу пише
  `login(token, email)` у стор, а кнопка «Вийти» - `logout()`.

`persist` - те, завдяки чому сесія переживає F5: стан серіалізується в
`localStorage` і повертається при старті. Свого коду нуль рядків.

### Крок 2 - маршрути і захищений маршрут

`Routes` замість тернарника. Скелет уже лежить у підказці `App.tsx`;
тридцять секунд подумайте про кожен рядок:

- `path="/login"` - публічна сторінка, її видно всім;
- `index` - головна адреса `/`: тепер там **мапа** (крок 4), список
  переїжджає на `/notes`;
- `notes/new` і `notes/:id` - створення і деталі; `:id` - шаблон: під нього
  підходить будь-яка адреса виду `notes/42`, значення читають `useParams()`;
- вкладені `Route` без `path` - обгортки: `ProtectedRoute` пускає або ні,
  `Layout` малює шапку навколо `<Outlet />`.

`ProtectedRoute` - друга половина кроку: сім рядків, і всі вони цілком
написані у підказці того файла. `replace` обов'язковий: без нього «назад»
поверне у захищену зону.

Переходи - `<Link to>`, з коду - `useNavigate()` (наприклад, після вдалого
входу: `navigate('/', { replace: true })`). Звичайний `<a>` перезавантажить
сторінку і зітре весь стан. Усі сторінки вже лежать у каркасі заготовками -
допишіть у них те, що позначено TODO.

### Крок 3 - дані через Query

`useEffect` і `load()` зі сторінки-списку мають зникнути **повністю**.
Хуки: `useNotes`, `useNote(id)`, `useCreateNote`, `useUpdateNote`,
`useDeleteNote` - кожен 5-8 рядків, зразок перших двох є у підказці файла.
Після мутації кеш не правимо руками:

```ts
onSuccess: () => qc.invalidateQueries({ queryKey: ['notes'] })
```

- і Query перечитає список сам. `queryKey` - **масив**, не рядок: ключ
  рядком - найчастіша помилка, `invalidate` тоді тихо не спрацьовує.
  `busy` теж більше не ваш: `update.isPending && update.variables?.id === note.id`.

### Крок 4 - мапа на головній

Нотатки у нас геоприв'язані (у кожної `lat` і `lng`), тож головною
сторінкою буде мапа OpenStreetMap з маркерами. Заготовка `MapPage.tsx`
уже в каркасі, і обидві відомі граблі в ній уже закриті:

- **висота контейнера** задана в `index.css` (`.map`) - Leaflet рахує
  розміри сам, і без явної `height` мапа має нуль пікселів;
- **іконка маркера** полагоджена на початку файла: у dev Leaflet шукає
  картинки за відносними шляхами, яких у збірці Vite немає.

Залишилось два рухи: розкладіть маркери з `useNotes()` (скелет - у
підказці файла) і клік по маркеру хай відкриває попап із посиланням на
`/notes/:id`. Дані ті самі, що й у списку, - кеш Query один, тому
перехід «мапа ↔ список» не смикає API, поки дані свіжі.

## Пʼять відмов, які виглядають як баг

| Симптом | Причина | Лікування |
|---|---|---|
| `No QueryClient set` у консолі | `useQuery` викликано поза провайдером | провайдери вже в `main.tsx` - значить, ви їх видалили або обгорнули не все `App` |
| Дані «спливають» самі собою | `refetchOnWindowFocus: true` за замовчуванням | вже виправлено у `main.tsx`: `staleTime` і `refetchOnWindowFocus: false` - не міняйте назад |
| Список не оновився після створення | `queryKey` - рядок, а не масив | `invalidateQueries({ queryKey: ['notes'] })` |
| F5 на `/notes/3` дає 404 | сервер шукає файл, якого немає | у деві це робить Vite; у проді - `try_files` у nginx |
| Після виходу видно чужі дані | кеш Query пережив зміну користувача | `logout()` і `location.assign('/login')`, а не `navigate()` |

Жодна з них не про React. Усі пʼять - про те, що дефолти бібліотек не
збігаються з очікуваннями. Перші дві у каркасі вже підкладені соломкою -
але знати їх усе одно треба.

**`npm install` - до будь-якої команди `npx prisma`.** Без установлених
залежностей `npx` мовчки тягне з реєстру НАЙСВІЖУ версію CLI (зараз це
Prisma 8), у якої інші команди - і ви отримаєте «No command registered for
`migrate`». Локальна CLI ставиться разом із залежностями.

## Стилі

`CSS Modules` (`NoteCard.module.css` → `styles.card`) або Tailwind - на вибір.
Критерій один: чи зможе наступна людина знайти, звідки взявся цей відступ.
У каркасі лежить простий глобальний `index.css` - його можна лишити, якщо
екранів мало і імена класів не бʼються.

## Чого тут немає - і це навмисно

- **серверних змін.** Бекенд із Пз4 не чіпаємо: уся практична - про клієнт;
- **SSR і мета-фреймворків.** Next.js робить те саме інакше

## Що здаємо

Репозиторій, у якому клієнт має мапу з маркерами на головній, ще три
сторінки з роутингом (список, деталі, створення), захищений маршрут,
сесію в сторі з `persist`, дані через Query з `invalidateQueries`,
стилізований інтерфейс - і всі сім перевірок вище проходять.
